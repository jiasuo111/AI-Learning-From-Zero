# 08_GRU

# 门控循环单元 GRU

> GRU 是 LSTM 的简化版，效果接近但参数更少、训练更快。


## 一、课程引入

### 1.1 LSTM 效果好，但有点复杂

LSTM 有三个门 + 一个细胞状态 C，参数量大，训练慢。

**能不能简化一下，效果还差不多？**

> GRU 就是答案。

### 1.2 GRU 是什么？

**一句话定义**：GRU（Gated Recurrent Unit，门控循环单元）是 LSTM 的简化变体，2014 年提出。

| 对比       | LSTM | GRU           |
| ---------- | ---- | ------------- |
| 门控数量   | 3 个 | **2 个**      |
| 细胞状态 C | ✅ 有 | ❌ 没有        |
| 参数量     | 多   | **少**        |
| 训练速度   | 慢   | **快**        |
| 效果       | 好   | **接近 LSTM** |

> 💡 **核心结论**：GRU 用更少的参数，取得了和 LSTM 差不多的效果。


## 二、GRU 的核心机制

### 2.1 只有两个门

| 门控                      | 作用                                  |
| ------------------------- | ------------------------------------- |
| **重置门（Reset Gate）**  | 决定“忘掉多少旧信息”                  |
| **更新门（Update Gate）** | 决定“保留多少旧信息 + 加入多少新信息” |

> 💡 **记忆技巧**：重置门 ≈ LSTM 的遗忘门，更新门 ≈ LSTM 的输入门 + 输出门。

### 2.2 核心思路流程

上一步的 hₜ₋₁
│
├──→ 重置门：从 hₜ₋₁ 中选出一部分 → 变成“中间态”
│
当前步的 xₜ
│
├──→ 中间态 + xₜ → 变成“候选 h”（新信息）
│
└──→ 更新门：候选 h 和 hₜ₋₁ 加权融合 → 得到新的 hₜ

text

### 2.3 你的理解（完全正确）

> “重置门是把上一步的 h 选出一部分变成中间态，输入部分是把中间态和当前步的 x 变成候选 h。更新门是把候选 h 和上一步的 h 变成新的 h。”

✅ **完全正确！** 这就是 GRU 的全部逻辑。


## 三、GRU vs LSTM 对比

### 3.1 结构对比

| 对比项 | LSTM | GRU |
|--------|------|-----|
| 门控数量 | 遗忘门 + 输入门 + 输出门 | **重置门 + 更新门** |
| 状态数量 | h + C | **只有 h** |
| 参数量 | 多 | **少 1/3** |
| 训练速度 | 慢 | **快** |
| 适用场景 | 长序列、复杂任务 | 通用任务、资源受限 |

### 3.2 效果对比

| 对比项 | LSTM | GRU |
|--------|------|-----|
| 长距离记忆 | 更好 | 好 |
| 短序列任务 | 好 | **接近 LSTM** |
| 训练稳定性 | 好 | **好** |
| 过拟合风险 | 高（参数多） | **低（参数少）** |

> 💡 **经验法则**：数据集大 → LSTM；数据集小或追求速度 → GRU。


## 四、API 使用

### 4.1 基本用法

​```python
import torch
import torch.nn as nn

# 定义 GRU
gru = nn.GRU(
    input_size=10,       # 输入特征维度
    hidden_size=20,      # 隐藏状态维度
    num_layers=2,        # 层数
    batch_first=True,    # 输入形状：(batch, seq, feature)
    bidirectional=False  # 是否双向
)

# 输入：(batch=4, seq_len=6, input_size=10)
x = torch.randn(4, 6, 10)

# 初始化隐藏状态
h0 = torch.zeros(2, 4, 20)   # (num_layers, batch, hidden)

# 前向传播
output, h_n = gru(x, h0)

print(output.shape)  # torch.Size([4, 6, 20])
print(h_n.shape)     # torch.Size([2, 4, 20])
```



### 4.2 双向 GRU

python

```
gru = nn.GRU(10, 20, num_layers=2, bidirectional=True)

x = torch.randn(4, 6, 10)
output, _ = gru(x)
print(output.shape)  # torch.Size([4, 6, 40])  # 双向 → hidden*2
```



## 五、优缺点

### 优点

| 优点            | 说明                       |
| :-------------- | :------------------------- |
| ✅ 参数少        | 比 LSTM 少约 1/3           |
| ✅ 训练快        | 计算量小，收敛快           |
| ✅ 效果接近 LSTM | 大多数任务中差距很小       |
| ✅ 缓解梯度消失  | 继承了 LSTM 的梯度传播优势 |

### 缺点

| 缺点                  | 说明                         |
| :-------------------- | :--------------------------- |
| ❌ 没有细胞状态 C      | 长序列上可能略逊于 LSTM      |
| ❌ 仍无法并行          | 必须逐时间步计算             |
| ❌ 被 Transformer 超越 | 长文本生成已转向 Transformer |

## 六、总结

### 一句话总结

> **GRU = LSTM 的轻量版，两个门搞定，效果接近，速度更快。**

### 什么时候用 GRU？

| 场景               | 推荐                        |
| :----------------- | :-------------------------- |
| 数据集较小         | ✅ GRU（参数少，不易过拟合） |
| 追求训练速度       | ✅ GRU（计算量小）           |
| 超长序列           | ❌ 用 LSTM（有 C 状态）      |
| 资源受限（手机端） | ✅ GRU                       |
| 通用任务           | ✅ GRU（效果接近 LSTM）      |
