# 11_bert

# BERT 模型

> BERT 是 NLP 领域里程碑式的模型，它让机器真正学会了“理解”上下文。ChatGPT 等大模型的成功，某种程度上可以追溯到 BERT 开启的预训练时代。


## 一、课程引入

### 1.1 回顾一下 Transformer

Transformer 有 Encoder 和 Decoder 两部分：

- **Encoder**：提取输入的特征（理解）
- **Decoder**：根据特征生成输出（生成）

**那如果我们只需要“理解”能力，不需要“生成”能力呢？**

> 比如文本分类、情感分析、问答系统——这些任务只需要理解输入的意思，不需要生成新内容。

**BERT 的答案**：把 Transformer 的 Encoder 拿出来，单独训练成一个“语言理解引擎”。


## 二、BERT 是什么？

**一句话定义**：BERT（Bidirectional Encoder Representations from Transformers）是一种**仅使用 Transformer Encoder** 的预训练语言模型，通过“完形填空”任务学会理解上下文。

### 2.1 核心特点

| 特点              | 说明                                       |
| ----------------- | ------------------------------------------ |
| **只用 Encoder**  | 没有 Decoder，只做理解，不做生成           |
| **双向上下文**    | 每个词同时看左边和右边的词（RNN 只能单向） |
| **预训练 + 微调** | 先在大规模语料上预训练，再在具体任务上微调 |

### 2.2 你的理解

> “BERT 在 Encoder 上面加了预测头，让 Encoder 学会‘完形填空’。就只有 Encoder，12层或者24层。”

✅ **完全正确！** BERT 本质上就是在 Transformer Encoder 上加了一个“预测头”，训练时让它做 MLM（完形填空）任务。


## 三、BERT 做了什么：完形填空

### 3.1 训练任务：MLM（Masked Language Model）

> MLM = Masked Language Model，中文叫“掩码语言模型”。

**具体做法**：

输入句子: 我 [MASK] 很 开 心
↓
BERT 要预测: [MASK] = “今”

text

```
> 💡 和 Word2Vec 的训练一样，训练完保存参数。但 BERT 的词向量是**上下文相关**的，“我”在“我爱你”和“你爱我”里不一样。

### 3.2 训练流程
```



原始句子: "我今天很开心"
↓
随机 Mask 15% 的词: "我 [MASK] 很 开 心"
↓
输入 BERT Encoder（12层/24层）
↓
输出: 每个位置的特征向量
↓
预测头（一个线性层）: 预测 [MASK] 位置是什么词
↓
计算损失（预测词 vs 真实词）
↓
反向传播更新 Encoder 参数

text

```
### 3.3 你的理解

> “训练阶段就是 MLM，把参数训练好之后，只要相同的句子进去，编码器提取的特征就是一样的了。”

✅ **完全正确！**

| 阶段 | 输入 | 输出 | 目标 |
|------|------|------|------|
| **预训练** | “我[MASK]很开心” | 预测 [MASK] = “今” | 学语言理解（学参数） |
| **使用时** | “我今天很开心” | 每个词的特征向量 | 提取特征，用于下游任务 |


## 四、预训练 vs 微调

### 4.1 预训练（Pre-training）

> 在大规模语料上做 MLM，让 BERT 学会“语言理解”的能力。

**特点**：
- 数据：大量无标注文本（维基百科、书籍等）
- 任务：完形填空（MLM）+ 下一句预测（NSP）
- 结果：得到一套**通用的语言理解参数**

### 4.2 微调（Fine-tuning）

> 在具体任务上继续训练，把“通用理解能力”适配到“特定任务”。

| 任务 | 微调方法 |
|------|----------|
| 文本分类 | 在 [CLS] 后面加分类头 |
| 情感分析 | 在 [CLS] 后面加二分类头 |
| 问答系统 | 在 Encoder 上加预测起始/结束位置的头 |
| 命名实体识别 | 对每个 token 输出做分类 |

### 4.3 你的理解

> “做文本分类的微调，这个阶段在微调训练一次，才能让他做文本分类的任务。这个阶段就是去训练出 CLS 的特征到分类这个阶段的参数了。”

✅ **完全正确！**
```



预训练阶段:
BERT Encoder（随机初始化）→ MLM 训练 → 得到预训练参数

微调阶段:
预训练参数（加载）→ 加上分类头（随机初始化）→ 分类任务训练 → 参数小幅更新
↓
CLS → 分类 的参数被训练出来
编码器参数被微调

text

```
### 4.4 微调的关键点

| 阶段 | 参数状态 |
|------|----------|
| 新加的分类头 | 随机初始化，主要靠微调阶段学习 |
| 原有编码器参数 | 加载预训练值，微调阶段**小幅更新**（学习率要小） |
| 整体策略 | 先用预训练参数，再用小学习率适配任务 |


## 五、[CLS] 标记的作用

### 5.1 为什么要有 [CLS]？

> BERT 每个 token 的输出都融合了全局信息，但 [CLS] 是特殊的——它没有具体语义，像一个“中性容器”，不会偏向某个词，所以能更公平地吸收整个句子的特征。

**具体做法**：
```



输入: [CLS] 我 今 天 很 开 心
↓ ↓ ↓ ↓ ↓ ↓
CLS 我 今 天 很 开 心
↓
取 [CLS] 的输出向量 → 代表整个句子 → 拿去分类

text

```
### 5.2 为什么不用其他位置？

| 位置 | 问题 |
|------|------|
| 第一个词“我” | 带有具体语义，可能偏向某个主题 |
| 最后一个词“心” | 位置靠后，可能受局部影响 |
| **CLS** | 中性、全局、无具体语义 → 最适合做句子表示 |

### 5.3 你的理解

> “[CLS] 本身没有具体的语义，像一个‘中性容器’，在交互时不会引入某个词的偏见，所以能更公平地吸收整个句子的特征。可以把 [CLS] 的输出向量当作整个句子的表示。”

✅ **非常准确！** 这就是 [CLS] 的设计初衷。


## 六、BERT vs Word2Vec

| 对比 | Word2Vec | BERT |
|------|----------|------|
| 词向量是否依赖上下文 | ❌ 固定向量 | ✅ 上下文相关 |
| 训练方式 | 预测上下文（CBOW/Skip-gram） | MLM（完形填空） |
| 双向上下文 | ❌ | ✅ |
| 能否微调 | ❌ | ✅ |
| 输出 | 每个词的固定向量 | 每个位置的上下文特征 |


## 七、核心总结

### 7.1 一句话总结

> **BERT = Transformer Encoder + MLM 预训练 + [CLS] 做句子表示 + 微调适配下游任务。**

### 7.2 知识结构图
```



BERT
│
├── 架构：只用 Transformer Encoder（12层/24层）
│
├── 预训练（Pre-training）
│ ├── MLM（完形填空）：随机 Mask 15% 的词，预测被遮掉的词
│ ├── NSP（下一句预测）：判断两句话是否连续
│ └── 输出：上下文相关的词向量
│
├── 微调（Fine-tuning）
│ ├── 加载预训练参数
│ ├── 加任务头（分类头、问答头等）
│ ├── 在具体任务上训练（学习率小）
│ └── 编码器参数小幅更新
│
├── 核心概念
│ ├── [CLS]：句子级表示（中性容器）
│ ├── 双向上下文：每个词同时看左右
│ └── 上下文相关词向量：“我”在不同句子中不同
│
└── 与 Word2Vec 的对比
├── Word2Vec：固定向量，双向，不能微调
└── BERT：上下文相关，双向，可微调
